# Kit specifications

## Feature contracts on the default branch

- [001 — Proxy Lifecycle Guard fail-closed follow-up](001-proxy-lifecycle-guard-plugin/spec.md): draft for bounded batch decisions and assignment handling. It does not authorize implementation or activation.
- [003 — Restart controller operations](003-restart-controller/spec.md): controller contract, shutdown amendment, later fixes and the operations workflow. [Plan](003-restart-controller/plan.md) · [Tasks](003-restart-controller/tasks.md) · [Offline quickstart](003-restart-controller/quickstart.md) · [Closeout](003-restart-controller/analysis.md#offline-closeout).
- [004 — Isolated LiteLLM rehearsal](004-isolated-proxy-rehearsal/spec.md): pre-implementation design for an offline configuration check and a separate opt-in native rehearsal. Neither command is available from this specification, and publication does not authorize implementation or qualification. See the [plan and entry gates](004-isolated-proxy-rehearsal/plan.md#gates-and-evidence), [task list](004-isolated-proxy-rehearsal/tasks.md), and [validation quickstart](004-isolated-proxy-rehearsal/quickstart.md). The entry gates bind evidence and authorization to the current spec and task hashes and normative packet digest.
- [005 — Project provisioning baseline](005-project-provisioning-baseline/spec.md): contributor setup, repository scaffolding, and opt-in release automation.
- [006 — Revision-bound task-review override](006-task-review-override/spec.md): explicit, default-off waiver of pending task review for exact validated revisions.
- [008 — Hermes exact quality-eval attribution](008-hermes-eval-attribution/spec.md): design draft. No transport is qualified and implementation is not approved. See the [plan and entry gates](008-hermes-eval-attribution/plan.md).

The maintainer moved the attribution draft from `002-hermes-eval-attribution` to 008 as a one-time exception to resolve a numbering conflict. For older references to that draft, use the 008 link above; `002` is not an alias for 008.

Feature numbers are stable identifiers, not a count of merged specifications. A gap can be reserved for branch-only work; do not renumber existing features to fill it. Keep each feature's spec and supporting artifacts in its own `specs/NNN-short-name/` directory. The [guard incidence-reduction contract](../docs/contracts/guard-incidence-reduction.md) is a separate operational contract.

Start in a dedicated kit worktree. Beads owns backlog and delivery status. Feature `tasks.md` files define the reviewed implementation sequence and acceptance evidence; their checkboxes are not a second backlog or a source of delivery status. The checked-in [Spec Kit scaffold and constitution](../docs/project-tooling.md#work-in-a-fresh-checkout) provide the Hermes-first baseline. Do not commit feature pointers, private approval records, or machine-local extension configuration. See the feature [plan](003-restart-controller/plan.md#gates-and-complexity) for implementation prerequisites.

Run the Spec Kit `verify_spec_md.py` and `verify_tasks_md.py` checks against the feature directory and follow the [offline quickstart](003-restart-controller/quickstart.md). Where a feature requires Spec Validate, follow the [checked-in validation and review workflow](../docs/project-tooling.md#install-hermes-commands-separately). For feature 003 the gate command is `bash .specify/extensions/spec-validate/scripts/bash/check-gate.sh 003-restart-controller`. If the extension or approval evidence is missing, the gate is not cleared. Never infer approval. A [maintainer override](../.specify/extensions/spec-validate/commands/gate.md) may waive waiting for an eligible review. It is not a validation, peer approval, or security-review waiver.
