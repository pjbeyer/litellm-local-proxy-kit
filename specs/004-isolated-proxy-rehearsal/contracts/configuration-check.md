# Contract: routine configuration check

## Invocation and admission

Proposed `make rehearse-check REHEARSAL_ROOT="$review_root" REHEARSAL_MANIFEST="$review_root/reviewed-check.json" REHEARSAL_SHA256="$reviewed_digest"`. All three arguments are required explicitly; the root and manifest path must be absolute. The checkout and its Makefile must be trusted. Treat invocation values as data, not shell or Make expressions; reject combined targets before any target recipe starts. If either rehearsal target is combined with any other goal (including the other rehearsal target), Make returns nonzero with a fixed usage diagnostic on stderr and no JSON on stdout; no lane is selected. The operator supplies a private staging directory dedicated to reviewed inputs, separate from installed deployments and controller roots. Never infer it from the working directory or environment. The caller must also use a trusted Make invocation; arbitrary Make flags, toolchain overrides and inherited Make control variables are not part of the interface. Review only credential-free inputs, not copies of live credential stores or settings containing resolved values.

Apply the [shared reviewed-input rules](rehearsal.md#shared-reviewed-input-rules) to the manifest and all check entries. No image root is used. Require the checkout, invocation toolchain, render dependencies and reviewed staging tree to reside on trusted local filesystems. The trusted caller establishes the checkout and toolchain placement before invocation; the check verifies the reviewed root and each input are on admitted local storage before reading content. Refuse unknown, network-backed or automatically mounted input storage; do not traverse or activate it to inspect the data. A version-1 check manifest is closed: `version: 1`, `mode: "configuration_check"`, `overlay`, `pin`, and optional `baseline_overlay`. Each file entry is exactly `{path, sha256}` with an absolute path beneath the same configured root and a lowercase 64-hex digest. The expected manifest digest is independent of that file. Refuse unknown or duplicate keys, wrong types, unstable or oversized content, native fields and native manifests. Bind the checked bytes before parsing or rendering; never reopen an admitted path to render it.

## Offline work and bounds

Run only the trusted checkout's parser, `core/render_config.py` render function and `core/config.template.header.txt` with already-installed trusted dependencies. Parse the admitted pin bytes as UTF-8 TOML, requiring a nonempty string `base_version` and a `patch_tip` of 7–40 lowercase hexadecimal characters. Treat all other pin metadata as opaque: do not resolve paths, sources, references or receipts. Do not call runtime provenance or sentinel entry points. Pass a fixed synthetic `HOME` (`/rehearsal-home`) explicitly; inherit no behavior-affecting environment or credentials. Render both overlays with the same trusted renderer, template and context. Derive `render_context_sha256` from a closed object `{version, renderer_sha256, template_sha256, parser_inventory_sha256, python, pyyaml, settings}` with `version: 1`. Hash the exact trusted `core/render_config.py` and tracked header bytes into their named fields; both renders must execute code derived from those exact renderer bytes and consume those exact header bytes. Use `{implementation, version, executable_sha256, inventory_sha256}` for `python` and `{version, inventory_sha256}` for `pyyaml`. Hash inventories as closed maps of component-relative names to exact-byte digests (no host paths). The parser inventory covers the exact reviewed checkout code used to parse and normalize admitted data, including comparison inputs; standard-library and package parser components remain covered by their respective inventories. The Python inventory covers the trusted interpreter distribution’s standard library and native runtime dependencies used during startup and rendering; the PyYAML inventory covers the trusted package’s importable files and native extensions. Use a trusted bootstrap and a stable trusted installation with no ambient import sources. Both entry points use the same read-only trust record supplied by the trusted local kit/toolchain installation, outside the reviewed staging root. The record binds renderer, header and parser inventory digests from the reviewed checkout revision and interpreter and dependency digests from trusted installation records established before the check. Never promote observations from the current invocation into expectations. If that reference is missing or mismatched, stop before renderer or dependency execution and return `failed` with `render_failed`. Before starting the render interpreter, the trusted bootstrap verifies its executable and startup dependencies against the trust record and establishes continuity of those verified objects into startup. If it cannot, both entry points emit bounded `render_failed` without starting that interpreter. Verify the expected renderer, parser and render dependencies before loading them, and bind both renders to the verified executable and exact render-affecting code used, including loaded native images. Do not use cached renderer or dependency bytecode unless its exact bytes are included in that identity. A mismatch detected at admission prevents rendering; lack of identity or continuity cannot yield `checked`. The fixed settings object is `{"HOME":"/rehearsal-home"}`. Use and identify the same trusted dependencies for both renders; an unidentified context is non-success. Hash the UTF-8 JSON object with sorted keys, ASCII escapes and no insignificant whitespace; do not include paths, ambient environment, or timestamps. The check is for reviewed data, not a sandbox or a compatibility check.

### Supported overlay fields (v1)

The proposal and any baseline use the same closed subset of the kit overlay. Required fields are marked below; other listed fields are optional. No coercion, nulls, unknown fields, or silently dropped settings.

| Field | Admitted value |
| --- | --- |
| `master_key_env` (required), `upstream.api_key_env` (required) | Environment variable name matching `[A-Z_][A-Z0-9_]*`; never resolved. |
| `upstream.api_base` (required) | Absolute HTTP(S) URL with a host and no userinfo, query, fragment, whitespace or substitution placeholders; held as data, never resolved or contacted. |
| `upstream.models` | Sequence of maps with required nonempty `name` and optional `timeout` and `stream_timeout` (positive integers in seconds). Model names must be unique. `*` is reserved for the wildcard flag. |
| `upstream.wildcard`, `upstream.wildcard_timeouts` | Booleans. `wildcard_timeouts` may be supplied only when `wildcard` is true. Require at least one named model or `wildcard: true`. |
| `litellm_settings` | Map with only Boolean `drop_params`, `modify_params` and `telemetry`, and positive integer `request_timeout` (seconds). |
| `router_fallbacks` | Sequence of maps with a unique `from` and a nonempty `to` sequence of distinct names; names must refer to declared named models. Preserve destination order. |

Names contain only ASCII letters, digits, `.`, `_`, `-` and `/`. Reject all other fields, including `extra_model_list`, `general_settings` overrides, `litellm_settings_addendum`, callbacks, and MCP servers. The renderer still generates `general_settings.master_key` as a reference. The check does not cover production-only settings: prepare a reviewed overlay in this subset or accept refusal; the check never strips unsupported fields on the operator's behalf.

Budget: manifest 16 KiB, pin 32 KiB, each UTF-8 overlay 256 KiB; at most 4,096 parsed nodes and nesting depth 24 per overlay. Use a safe, bounded YAML subset: reject aliases/anchors, merge keys, duplicate or non-string map keys and explicit tags. Cap each in-memory render at 1 MiB and the complete CLI operation at 10 seconds, including render-context identity collection and verification; on timeout fail without partial output. No file creation or modification by the CLI or Make recipe, including temporary files, interpreter caches, rendered configuration or a run ledger. No downloads. Raw data, parser exceptions and host-local fields never reach stdout/stderr.

## Result and process status

The standalone CLI and Make both emit exactly one closed JSON object on stdout (maximum 4 KiB) for every controlled outcome of a dispatched single rehearsal-check target or standalone check CLI: `version: 1`, `mode: "configuration_check"`, `runtime_not_exercised: true`, `status` (`checked`, `refused`, `failed`). `checked` includes `manifest_sha256`, `overlay_sha256`, `pin_sha256`, `template_sha256`, `render_context_sha256`, `rendered_sha256`, and `categories_present`. It includes `comparison: null` when no baseline was supplied, otherwise a closed object with `baseline_overlay_sha256`, `baseline_rendered_sha256` and `changed_categories`. Category IDs in fixed order are `model_list`, `litellm_settings`, `general_settings`, and `router_settings`; any other rendered top-level key is a render failure. Compare their parsed values in memory (mapping order ignored, sequence order significant); list only changed categories, including additions and removals. Emit category IDs in fixed order and never include caller-defined keys, values, names, paths or raw diffs. An empty comparison list means no differences in those categories under this render context; `null` means no comparison. All admitted inputs are reviewed and secret-free; use only references, never resolved credentials.

For `refused` and `failed`, omit all success fields and include one fixed `reason`: `input_invalid` or `digest_mismatch` (refused), `render_failed`, `output_limit` or `deadline` (failed). Ordinary process interruption without a result is non-success. The underlying CLI returns 0, 78, or 1 respectively; GNU Make returns nonzero on recipe failure (normally 2), so Make consumers use the typed result for disposition. Check success requires both exit zero and a valid `checked` object. Make must not mix this target with any other target. Neither `checked` nor absence of output establishes runtime behavior, equality to production, or approval to stage or activate anything.
