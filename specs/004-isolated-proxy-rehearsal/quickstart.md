# Validation quickstart: isolated rehearsal

These are planned commands and acceptance steps, not evidence they work today.

1. **Before implementation:** Require a passing current-revision Spec Validate gate, applicable independent review and separate owner authorization bound to the same normative packet, as specified in the plan. Do not modify installed proxy, controller or shared tooling.
2. **Routine check:** On a workstation with a qualified offline toolchain and pre-start trust record, feed one reviewed bundle through a pipe, using the independently recorded bundle digest and command in the [configuration-check contract](contracts/configuration-check.md). Expect exit zero and one valid `checked` object with `runtime_not_exercised: true` and bundle, manifest and trusted render context digests. No VM, image, candidate runtime bundle, external drive or separate runner. Exercise baseline and no-baseline outcomes, changed bundle and member bytes, invalid or oversized streams, unsupported settings, and stdin held open without EOF. Verify no proposal path lookup, candidate or managed access, or writes. For each entry point verify a controlled deadline or startup/render failure produces the specified closed non-success and no rendered data. Mixed goals stop before any recipe, with stderr only. Run the routine and owner-maintenance regressions in T013.
3. **Native opt-in:** Qualify the backend with inert fixture inputs and disposable sentinels before candidate work (T002); repeat the boundary and teardown matrix on the finished integration before native acceptance (T009). An unavailable backend yields a native refusal, never a configuration result. Use the [native contract](contracts/rehearsal.md) for the manifest and command. A fixture-only startup is not acceptance.
4. **Native acceptance (T010):** In a separately authorized same-host window, use two separately reviewed and pinned manifests changing only `fixture_trace`. Require exit zero and a valid `passed` receipt for each run. Compare admitted artifact digests other than the manifest digest for equality. Require unchanged prepared runtime, exact fixture YAML and proposal digests, a changed effective launch digest, the expected supervisor-observed counter behavior for each Boolean, reported exercised routes, explicit substitutions and exclusions, and proved closure for both runs. Require equal candidate build IDs across the pair. For each run, compare the candidate ID from its validated receipt with the independently observed managed listener ID from verified, process-bound provenance. Those full source commits must differ; missing, unbound or incomparable evidence is inconclusive. Before starting, select observation in the trusted acceptance harness and wait for the observer to be ready. The independent read-only observer names the managed assets and controller state evidence to observe: installed file digests, policy, qualification, bootstrap and durable operation/recovery state. For each run record the same managed listener process identity before, during actual candidate coexistence, and after. Record the managed sample start and end on the same host monotonic clock, both strictly within the trusted liveness bracket of at most five seconds, bound to the exact candidate listener verified by that run’s receipt; compare every declared asset and state item before/after for equality. An absent or ambiguous observation is inconclusive. Evidence from a separate runner is not same-host coexistence evidence for this Mac. Never alter live state to make observations match; any rerun needs a new authorized window.

Neither result authorizes staging, qualification, restart or activation.
