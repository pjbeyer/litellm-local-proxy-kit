# Controller contract reconciliation

Read this with the [initial controller contract](controller.md) and [shutdown amendment](shutdown.md). These notes take precedence where their original assumptions differ from the landed controller. [Historical plans](../history/) and incident receipts do not prescribe new live actions.

- **Deployment closure:** `Runtime.qualify` checks that the policy-bound deployment source has `deploy.conf.sh`, the named deployment's overlay, credentials manifest and pin, and a matching native receipt when applicable. A rendered config directory is not a deployment root. This is a structural check, not a replacement for installer verification, drift and preflight in `prepare`.
- **Runtime binding:** `Runtime.freeze` compares current kit facts, installed proxy plists and manifest to boot-time facts, and checks the installed controller's byte/mode facts against the install receipt when present (fixture fallback to kit facts). Separately, `Runtime.qualify` requires the controller copies to match the loaded controller source facts and validates the qualification and canary bindings. Do not infer that one matching axis clears another. See `core/restart_control/runtime.py` for these two checks rather than the original plan's single-source shorthand.
- **Recovery:** the post-restart changes allow settled, explicitly dispositioned manual recovery history to remain without an active fence. Recovery that is unresolved still blocks. The operator reconciles using the exact generation's contract; no generic state-deletion or auto-recovery script is authorized.

They are not a current readiness verdict or permission to replay any operation. Existing refusal dispositions remain in force.
